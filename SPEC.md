# Трекер целей — Telegram-бот на Spring Boot

## Что делает MVP

- Добавить дело в список на день.
- Отметить дело выполненным до 24:00.
- В 08:00 бот присылает итог вчерашнего дня: выполнено X из Y. Днём 2–3 напоминания о невыполненных делах с мотивационной цитатой.
- В конце недели (воскресенье, 23:59 или понедельник 00:05) — полная статистика и метрика продуктивности.

## Стек (всё бесплатно)

- Java 17+, IntelliJ IDEA Community
- Spring Boot (start.spring.io): Spring Web, Spring Data JPA, PostgreSQL Driver (или H2 для старта), Lombok
- Библиотека `org.telegram:telegrambots-springboot-longpolling-starter` + `telegrambots-client`
- GitHub для кода
- Позже: Docker + VPS / Oracle Cloud Free Tier

## База данных

Для MVP — H2 в файловом режиме: данные лежат в файле `./data/tracker.mv.db` и не стираются при перезапуске. Для боевого запуска — PostgreSQL в Docker; код не меняется, только конфиг.

Зависимость в `pom.xml`:

```xml
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>
```

Настройки в `application.yml`:

```yaml
spring:
  datasource:
    url: jdbc:h2:file:./data/tracker;AUTO_SERVER=TRUE
    username: sa
    password:
  jpa:
    hibernate:
      ddl-auto: update
  h2:
    console:
      enabled: true
      path: /h2-console
```

- `jdbc:h2:file:` — файловый режим; `jdbc:h2:mem:` был бы в памяти (данные теряются).
- `ddl-auto: update` — Hibernate сам создаёт и обновляет таблицы по сущностям.
- H2-консоль: http://localhost:8080/h2-console — посмотреть таблицы прямо в браузере (нужна зависимость Spring Web).
- Папку `data/` добавить в `.gitignore`.

Переход на PostgreSQL: заменить зависимость на `org.postgresql:postgresql`, а `url` на `jdbc:postgresql://localhost:5432/tracker` с логином и паролем; позже заменить `ddl-auto: update` на миграции (Flyway).

## Модель данных

**User** — id, telegramChatId, timezone, createdAt

**Task** — шаблон дела: id, userId, title, active (bool), createdAt

**TaskEntry** — отметка за конкретный день: id, taskId, date, done (bool), doneAt

Идея: Task — это «читать 30 минут», а TaskEntry — «читал ли я 6 ноября». Каждый день для активных задач создаются новые TaskEntry.

## Команды бота

- `/start` — регистрация пользователя по chatId
- `/add Читать 30 минут` — добавить дело
- `/today` — список дел на сегодня с кнопками «✅ Выполнено»
- `/remove` — убрать дело из списка
- `/week` — статистика за текущую неделю по запросу

## Планировщики (@Scheduled)

1. **08:00 каждый день** — подсчитать вчерашние TaskEntry, отправить «Вчера выполнено 3 из 5 (60%)», создать TaskEntry на новый день.
2. **Конец недели** — недельный отчёт.

Важно: использовать таймзону пользователя, а не сервера (`@Scheduled(cron = "0 0 8 * * *", zone = "Europe/Moscow")` для начала).

## Напоминания и мотивация

В 13:00, 17:00 и 21:00 бот проверяет сегодняшние TaskEntry. Если есть невыполненные — присылает список и одну случайную мотивационную цитату. Если всё выполнено — напоминание не отправляется (или короткое «Красава, день закрыт»).

- Время напоминаний вынести в настройки (`application.yml`), позже — команда `/reminders` для своего расписания.
- Цитаты хранить в таблице **Quote** (id, text, author) или в файле `quotes.json` в ресурсах; стартовый набор — 30–50 цитат (Дэвид Гоггинс, Джокко Уиллинк, Марк Аврелий, Сенека, цитаты из прочитанных книг).
- Не повторять одну цитату чаще раза в неделю.
- Тон: жёсткий, без сюсюканья — «Ты ещё не сделал 2 из 4. Вставай и делай.»

## Недельная статистика и метрика

- Процент выполнения за неделю: выполнено / всего.
- По каждому делу: сколько дней из 7.
- Лучший и худший день.
- Серия (streak): сколько дней подряд выполнено 100%.
- Сравнение с прошлой неделей: ↑ или ↓ на N%.
- **Productivity score 0–100**: например 70% веса — процент выполнения, 30% — стабильность (сколько дней было выполнено хотя бы 80%).
- Оценка словами: 90+ «Огонь», 70–89 «Хорошо», 50–69 «Средне», <50 «Проленился».

Потом можно добавить картинку-график (библиотека XChart).

## Пошаговый план

1. Сгенерировать проект на start.spring.io, запустить пустое приложение.
2. Создать бота через @BotFather, получить токен, положить его в `application.yml` (не коммитить в GitHub!).
3. Сделать эхо-бота: отвечает тем же текстом. Проверка, что связь работает.
4. Добавить сущности User, Task, TaskEntry и репозитории.
5. Реализовать `/start`, `/add`, `/today`.
6. Inline-кнопки «✅ Выполнено» и обработка нажатий (CallbackQuery).
7. Утренний итог дня в 08:00 и дневные напоминания с цитатами.
8. Недельный отчёт и метрика.
9. Покрыть сервис статистики unit-тестами (JUnit 5), а логику — интеграционными тестами (Testcontainers + PostgreSQL). Это твоя сильная сторона как QA.
10. Docker и деплой на сервер.

## Как это будет работать на старте

Запускаешь приложение у себя на компьютере — бот работает, пока компьютер включён. Когда всё отлажено, переносишь на сервер, чтобы работал круглосуточно.
